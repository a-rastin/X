# S43 — Implement bounded provider CPT estimation and tool bridging (2026-10-09)

Bounded provider CPT estimation with a real T6 tool bridge. One adapter
attempt performs a single pinned outbound payload, optional provider-requested
reads over the same real MCP transport returning the same persisted
projection, and shared strict CPT validation. No nested retries, no template
drafting through the provider, no direct-call bypass.

## Implementation (no existing behavior changed except the adapter target)

File only: `backend/src/x_insight/reasoning/provider.py` (+700/-14):

- `BoundedProviderAdapter` — one bounded estimation attempt: builds the
  pinned outbound payload, enforces capability mode, bridges permitted tool
  calls over real MCP, validates the candidate with the shared strict
  validator, enforces tool/request budgets, maps errors to an explicit
  retryability taxonomy. One adapter attempt never implements hidden nested
  retries.
- `build_outbound_payload` — pinned request contains only question prompt,
  fixed network/CPT contract, persisted projection, strict CPT response
  contract, and the one permitted tool declaration.
- Shared strict validator reusing `models.inference.validate_cpts` — both
  schema-capable and JSON-only capability modes share the same validator.
  Rejects extra prose, ambiguous responses, and
  malformed/truncated/oversized output.
- `DeterministicProviderEndpoint` test double — deterministic external HTTP
  endpoint for the estimation matrix; assertions inspect
  `endpoint.captured` external requests, not internal mock calls.
- `ControlledStubAdapter` unchanged (S44 queue control path untouched).

No frontend/content/migration/queue/MCP/snapshot/worker changes. No frontend
change required (confirmed by dev-frontend check: no `W/` files, templates
never pass through the provider for drafting).

## What works

- Pinned outbound payload (prompt + fixed contract + persisted projection +
  strict CPT schema + one tool declaration) is what the endpoint receives.
- Initial and provider-requested reads traverse the same real T6 transport
  and return the same persisted projection with correlation IDs preserved;
  the model cannot supply its own authorization metadata.
- Both capability modes share one strict validator; invalid CPT content
  fails rather than being repaired, truncated, or silently normalized.
- Error taxonomy distinguishes retryable (timeout/transient/rate-limit)
  from configuration failure; budgets (10 tool calls, context/output
  limits, no nested retries) are enforced per attempt.
