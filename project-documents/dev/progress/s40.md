Public T1 seams (author context only):

- `POST /api/v1/encounters/{id}/generation-batches` returns `202` with
  batch ID and ordered question progress. Carries the expected source
  revision; wrong-author, invalid, or stale starts are denied without
  partial creation.

  progress/transparency for the author's own run.

Fingerprint / projection / gate semantics:

- Analysis fingerprint `analysis-fingerprint-v1`: canonical UTF-8 JSON
  over analysis-visible patient/draft facts, reconciled medications,
  baseline clinical facts, and pinned content. Excludes notes,
  names/identifier/phone unless an explicitly permitted analytical field
  is needed (identifiers and names are never model inputs), UI state,
  and secondary-plan edits. A run additionally pins network/bundle, DDI,
  prompt/template/mapping, provider configuration, and engine versions.
- Question projection `question-projection-v1`: per question, only its
  represented variables appear, each with node ID, patient type,
  observed/not-assessed/missing/conflict status, source path/revision,
  and explicit null when unavailable. A mapping trying to read
  notes/unrelated history is rejected regardless of prompt wording.
  Notes, names, Patient ID, unrelated history, other questions'
  fields/results, and secrets are excluded.
- Gates evaluated against saved facts: true → `ready`, false →
  `not_applicable` with reason, required-unknown → `needs_clarification`,
  stopping later questions. Reasons are persisted; undeclared
  cross-question result inputs are forbidden.
- Freshness: note-only edits leave fingerprints unchanged and do not
  invalidate probability acceptance; relevant analytical/applicability
  edits invalidate affected question results and acceptance. Immutable
  old snapshots remain author-readable history. Signed snapshots preserve
  the full displayed record including notes and demographics even when
  those fields are not analytical.

## What works

- Batch start freezes allowed facts/version references and creates
  ordered question work in one transaction; repeated eligible triggers
  reuse work without partial creation on denied starts.
- Each question projection carries exactly its represented variables
  with typed state and source references; notes/identity/unrelated
  fields are absent from the model-facing shape.
- Note-only changes preserve fingerprints and acceptance; relevant
  changes invalidate only affected results while old snapshots stay
  readable.
- Gates persist ready/not_applicable/needs_clarification with explicit
  reasons and no posterior chaining.
