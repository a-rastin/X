# S44 — Durable leased jobs and global admission (2026-10-09)

S44 is implemented as a queue slice over saved S40 snapshots. Creating a
generation batch in one transaction freezes facts and enqueues the first
eligible job atomically; repeated same-fingerprint triggers reuse the run;
relevant edits supersede the prior active generation (old jobs cancelled,
history retained) so sequential edits keep S40 history while never leaving
two active generations. Two workers share two global provider slots via
short claim transactions (`SKIP LOCKED`, deployment-row serialization),
lease/heartbeat (15s/120s), fencing token + deployment generation checks,
and persistent fair rotation (round-robin across physicians, FIFO within).
Saturation returns visible busy state without deleting drafts/jobs. Expired
leases are reclaimed with old tokens fenced; restarts retain attempts +
terminal artifacts. One `run_once()` drives tests and polling. Preparation
uses real snapshot/gate logic (`snapshots.py`) plus a controlled stub
provider adapter that S43/S45 will complete; no queue collaborators mocked,
no full MCP/estimation, no local-calculation execution (schema reserved).
Synthetic single-question scope per tasks.md S44; T8 reuses S40 POST/GET
with queue visibility extended on GET only.

Public T8 seams (author context only; no unrelated endpoints):

- `POST /api/v1/encounters/{id}/generation-batches` returns `202` with the
  batch (reused when same fingerprint). Wrong-author/invalid/stale denied
  without partial rows; full queue is `429 QUEUE_FULL` (retryable).
- `GET /api/v1/generation-batches/{id}` exposes frozen projection,
  freshness, plus `job` (queued|leased|succeeded|failed|cancelled, no
  tokens), `attempts` count, and `queue` (`busy`, `leased_count`,
  `queued_count`, caps, `queue_position`).

Fingerprint / eligibility / fencing semantics:

- Fingerprint reuse covers facts + pinned package; encounter-row lock plus
  deployment lock serialize concurrent triggers (4-thread same-fingerprint
  probe yields one batch id).
- Claim eligibility reuses real logic: draft lifecycle, active author, gate
  ready, fingerprint freshness (stale cancels), `next_eligible_at`, one
  leased per batch, `SKIP LOCKED`, fair order (oldest grant NULLS FIRST,
  then oldest job). No DB tx while awaiting the provider.
- Commit fences on lease token + unexpired deadline + deployment generation;
  stale/account/lifecycle re-checks cancel without late artifacts. Expired
  leases reclaim to queued (in-flight attempt marked `LEASE_EXPIRED`,
  grants revoked); heartbeats extend live leases only.

## What works

- Batch start + first eligible job atomic; same fingerprint reuses; edits
  supersede to one active with full history; queued-cap busy.
- Two workers share two slots; one run never executes twice; fair rotation
  + FIFO; busy visible with drafts/jobs intact.
- Expiry reclaim, heartbeat, fencing token + deployment checks, restart
  retention, one deterministic `run_once()`.
- Real snapshot/gate checks on claim and commit; stub provider outside any
  tx; local class reserved in schema.

## Follow-up 2026-10-09 — Spec-review fixes (S44+S41 worktree, fixed point 34e467a)

Must-fix applied, one red→green slice at a time via `/tmp/opencode` probes
on real PostgreSQL (existing 14 queue + 13 MCP preserved):

- Reuse no longer resurrects dead history: `find_reusable_batch()` now
  returns only active batches (ready run with queued/leased job, or
  jobless non-ready/pre-S44 for backfill); terminal
  cancelled/failed/succeeded never reuse, older same-fingerprint actives
  still reuse. Probe: active reuses, cancelled→`None` + HTTP new id,
  failed→`None`.
- Slots no longer count dead leases: `claim_next_job()` reclaims expired
  leases (`now`) after the deployment lock before slot admission; live
  leases still report `busy`, expired reclaim then claim. `run_once()`
  reclaim kept (idempotent). Probe uses deterministic `t0`/`t0+181s`.
- Router docstring corrected: different-fingerprint supersedes (cancel +
  history, never 409); `409` is idempotency-key conflict only. Matches
  `snapshots.start_generation_batch` + S44 supersede-cancel design.
