Backend implementation already existed in the working tree (migration
0014, probability_review service/router, reasoning queue/worker local path;

## Scope and synthetic basis

Tasks.md S48b §§1-4 (FR-53, FR-55-56, FR-58, FR-43, NFR-04, NFR-06;
`BT/worker/test_local_calculation.py` T1/T8):

- §1 completed adjustment atomically clears acceptance (pointer move),
  marks recalculating, queues the exact saved revision/hash and runs only
  the fixed network/template/configuration with empty evidence.
  Provider/MCP disabled never affects the path; unrelated
  questions/DDI/generation stay unchanged. Independent literals: baseline
  80/20 unchanged, posteriors A 60/40 → [0.60,0.40],
  B → [0.66,0.34] (`0.10*0.60+0.70*0.40=0.34`).
- §2 newer adjustment/reset fences older responses; superseded results stay
  historical. Exact current/displayed revision IDs + freshness; never label
  earlier as current. Sequential rev1→rev2: after rev1 success current stays
  rev2/50,50 displayed rev1, then rev2 success flips to rev2.
- §3 numerical failure retains CPTs + separately labeled earlier success.
  Local retry same revision without re-estimation. Reset creates an audited
  baseline-equal revision with verified original-result reuse, clears
  acceptance, retains history; stale inputs still require regeneration.
  Failure is forced via a public-seam single-absent-branch template
  (`TEMPLATE_NO_MATCH` when B flips to yes-majority); retry/reuse proves
  zero provider calls. Reset `reused_from_baseline_id` equals the baseline.
- §4 restart resumes eligible durable jobs with leases/idempotency;
  deactivation/discard prevents late publication. Provider saturation (2
  leased generations busy) permits independent local progress with zero
  provider calls. Pending superseded jobs coalesce without deleting
  revisions.

Depends DONE: S48a (adjustments/redistribution), S44 (leased queue), S47

NOT modified: S48c acceptance UI, S48d freshness, S49 signing.

## What works

- T1/T8 §1: recalculating with exact revision/hash, local-only success with
  fixed snapshot + empty evidence (`engine local_empty_evidence`,
  network/query/template pinned), `stub.calls == []` even with a failing
  stub, baseline 80/20 preserved, unrelated batch/generation unchanged.
- T1/T8 §2: sequential + coalesced rev1→rev2 fencing; pending shows
  current rev2/50,50 with displayed rev1/0.66,0.34 and
  `current_result_matches False` + `calculation_result None`; rev2 success
  flips to rev2/0.42,0.58 with both results retained in order.
- T1/T8 §3: `TEMPLATE_NO_MATCH` failure retains 60/40 + 20/80 CPTs with
  displayed rev1; retry requeues the same revision/hash with zero provider
  calls (queued coalesce + solved idempotent + failed same-row); reset is
  baseline-equal with `reused_from_baseline_id`, 80/20 + 0.78/0.22 reuse,
  history retained; stale edits keep `input_freshness.stale True` across
  reset/retry; reset/retry 409/412/422 without pointer moves.
- T1/T8 §4: restart via fresh `TestClient` login resumes the queued local
  with idempotent replay (one job, one result); deactivation + discard
  cancel without results or provider calls (failed + cancelled jobs);
  2 leased generations busy while local succeeds independently;
  superseded queued jobs coalesce without deleting revisions.
