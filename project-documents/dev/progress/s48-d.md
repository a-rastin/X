## Scope and synthetic basis

- §1 represented/applicability changes mark ONLY affected runs out of date
  and invalidate ONLY affected acceptance. Stranger reads/writes are generic
  403 without draft content (`percentages`/`h_q1_a` absent). Unrelated
  questions stay fresh/accepted. Another physician's permitted shared read
  (chart) carries no draft content; the shared demographics-edit route that
  also stales without granting draft access belongs to S51 (hook documented,
  not built here).
- §2 regenerate affected applicable questions sequentially under the
  encounter's pinned bundle, retaining old baselines/adjustments/history and
  unaffected valid references. New QuestionRuns establish new originals; no
  old adjustments transfer silently. Captured provider requests prove
  affected-only (1 call for Q1, 0 for carried Q2).
- §3 applicability transitions refresh the question set (ready →
  not_applicable with Q1 carried, zero LLM calls); DDI-only (meds-only)
  changes refresh with zero LLM calls via per-question carry and immediate
  proposal assembly; activation never rebases existing encounters (old
  `pinned_bundle` byte-identical after new batches). S46
  `test_freshness_new_batch_old_proposal_immutable` updated to the S48d
  DDI-only expectation (0 calls, carried baselines, new DDI proposal, old
  immutable) — the S46 2-call expectation contradicted plan §4.2.
- §4 note-only and plan-text edits do NOT regenerate and preserve acceptance;
  reset/retry of a stale run stay stale (cannot restore eligibility);
  regenerated originals require exact review before accept (old input hash →
  409, then exact new accept → 200).

## Implementation (reuse-first, minimal diff)

Extended (backend only, no migration — `input_hash` column reuses per-question
hash semantics; old batch-hash rows safely mismatch as stale):

- `reasoning/snapshots.py` — `QUESTION_INPUT_SCHEMA_VERSION`,
  `question_input_hash(projection_hash, gate_status)`,
  `compute_question_freshness(run, batch, draft_data)` (recomputes typed
  projection with the stored `source_revision` + gate from the frozen
  `pinned_package` manifest; stale on hash or status move; notes/plan/UI/
  identifying fields excluded by S40 allowlists; legacy rows fall back to
  batch comparison), `get_question_input_freshness(session, run, batch)`
  (read-only, missing encounters report current),
  `_projection_values_key(projection)` (typed values ignoring revisions) +
  `_carried_baselines_per_question(...)` (carry when values+gate+package
  match, revisions ignored; DDI-only/unrelated-field → zero LLM calls).
  `start_generation_batch` merges per-question carry with S47 whole-print
  carry, enqueues only the first non-carried ready run, and assembles
  immediately when all ready runs are carried (DDI-only path).
- `reasoning/router.py` — GET `.../review` keeps batch `freshness` for the
  batch view but derives `input_freshness` per-question for acceptance.
- `probability_review/router.py` — POST `.../acceptance` checks per-question
  freshness (`stale` → 409 `STALE_INPUTS`, `input_hash` → per-question
  `REFERENCE_MISMATCH`); stored `input_hash` is now the per-question hash.

## What works

- T1/T8 §1: `h_q1_a` yes→no stales Q1 (`stale` true, `is_accepted` false,
  accept → 409 `STALE_INPUTS` with no write) while Q2 stays fresh/accepted
  with `80/20` intact; stranger batch/review/acceptance are generic 403
  without `percentages`/`h_q1_a`.

  projection values while Q2 values match ignoring revisions, retains the old
  batch (old Q1 1 revision + baseline readable), starts new runs with zero
  revisions/acceptances, then exactly 1 captured request for `s48d_q1`
  (sequential, Q2 carried with the same `effective_hash` as its old baseline;
  new Q1 is a new baseline ID with `80/20` shape).
- T1/T8 §3: gate true→false yields ready/not_applicable with Q1 carried and
  zero provider calls (`probe.calls == []`); meds-only change leaves both
  `input_freshness.stale` false, carries both baselines with zero calls, and
  retains `per_question` pins across batches.
- T1/T8 §4: proposal-page note + `secondary_plan` edit preserve
  `is_accepted` with the same acceptance ID; relevant edit stales; reset +
  retry (+ drain) stay stale/unaccepted; regenerated Q1 starts unaccepted
  with empty history, rejects the old input hash (409), then accepts its
  exact new review (200).
