### Red→green slices + seams (T4/T1; tasks.md S19 steps 1–4)

- Step 1 — pair identity + batched indexed lookup (T4; `BT/ddi/test_checker.py` slice 1): A/B and B/A yield the same canonical `(drug_a, drug_b)` + identical evidence; three unique drugs yield three pairs with no self-pairs; duplicate aliases (same catalog twice, or twice alongside a second drug) collapse and never create self-pairs. Fingerprint is order-independent. Lookup is one batched indexed query over `(release_id, pair_key)` (`ix_ddi_evidence_release_pair`) — engine-listener proof asserts exactly one `ddi_interaction_evidence` statement for three pairs, no N+1 per-pair queries.
- Step 2 — evidence aggregation + severity + direction (T4; slice 2): known evidence produces `interaction_found` with every assertion retained verbatim (`source_severity` verbatim, management prose stays in `raw_text`, `management` only from approved `correction.corrected_value`, spans/checksums/`source_hash` present); highest known severity follows display-only priority `contraindicated > serious > monitor_closely > minor > unknown` (never a clinical score); `conflicts[]` lists distinct severities when >1; `has_unknown_severity` stays visible and never hidden as low severity (`minor` still outranks `unknown` when no higher known exists; `contraindicated` outranks all known); directional descriptions retained as separate rows (Alpha→Beta `serious` + Beta→Alpha `monitor_closely` stay two rows with distinct `raw_text`; duplicate directions from independent sources never merged). Source-backed Sitagliptin/Ofloxacin fixture: real Sitagliptin parsing keeps Ofloxacin in both categories (`monitor_closely` "pharmacodynamic synergism" + `minor` "unspecified interaction mechanism" worked literals), and the same both-categories pattern flows into checking (`monitor_closely` highest, conflicts `{monitor_closely, minor}`, 2 evidence rows).
- Step 3 — explicit coverage vs unavailable (T4; slice 3): explicit `released_complete` without evidence produces `covered_no_listed_interaction` with basis `reviewed_complete_coverage` (never "safe"/"no interaction" — both strings asserted absent from the report JSON); `released_limited` pairs without rows produce `coverage_unavailable` with basis `limited_coverage_unavailable` and release `limitations` copied into the report, while known limited pairs with evidence still resolve `interaction_found`; zero/one-drug reports retain uncovered-catalog warnings (`limitations` non-empty on empty input, `coverage_unavailable_medications` carries the single drug in limited but stays empty in complete). Unresolved source concepts stay in ingestion review — unknown catalog IDs raise `422`, never a new free-text medication input.
- Step 4 — pinning, refusal, drug-only HTTP, offline (T4 + T1; slice 4 + `BT/http/test_ddi.py`): report pins `dataset_version` + `catalog_version` (`terminology_version`) + 64-hex `medication_fingerprint` (`canonical_hash({medications: sorted concept_ids, dataset_version})`) + `generated_at` (`Z`); refuses invalid dataset/configuration (`422 INVALID_DATASET_VERSION`/`INVALID_MEDICATION(S)` on bad format/types, `404 DATASET_NOT_FOUND` on unknown `ddi-<12hex>`); `POST /api/v1/ddi/check` + `GET /api/v1/drugs` enforce role/session (any active admin or physician session may call; anonymous `401`, missing/wrong CSRF `403` on the POST mutation, revoked/logout session `401`; `GET /drugs` needs no CSRF); drug-only input `extra=forbid` rejects `dose`/`unit`/`route`/`frequency`/`status`/`unknown_label`/top-level extras `422` even if forged, and noncatalog IDs are `422` (never accepted as free text); `GET /drugs` supports `query` (case-insensitive substring over canonical/catalog, whitespace-normalised) + bounded `limit`/`offset` (`parse_pagination` 25/100, `422` over bounds) + explicit `dataset_version` (defaults to `latest_release_version`), with `404` on bad/missing versions; executes with external network disabled (socket-guarded `check` + HTTP round-trip both succeed).
- Seams: T4 (checker) + T1 (HTTP) only. No T2/T3/T5–T10 exercised in S19.

### Local loop for next agent (S20+)

- Checker (T4): `check(engine, medications: list[catalog_drug_id], dataset_version: ddi-<12hex>) → DDIReport` from `x_insight.ddi.checker` (or `DDIChecker(engine).check(...)` with engine injected); `medications` is drug-only catalog IDs (duplicates collapse, never self-pairs); unknown IDs raise `CheckError 422`; bad version format raises `422`, missing version raises `404`, non-released status raises `503 DATASET_UNAVAILABLE`.
- Public readers (same interface `check` uses internally; callers use the owning module, never private helpers or foreign tables per plan §§3.2/12.1): `get_release_row(engine, version)`, `list_concepts(engine, release_id)` (catalog-only, display order), `latest_release_version(engine)` (oldest-first, publish-compatible; `None` when no release → HTTP `503`).
- Report shape (pinned for S20): `{dataset_version, catalog_version, medication_fingerprint (64-hex, order-independent), resolved_medications[]: {catalog_drug_id, concept_id, canonical_name, concept_type}, coverage_unavailable_medications[] (all resolved in limited, empty in complete), pairs[]: {drug_a, drug_b (sorted catalog IDs), status: interaction_found | covered_no_listed_interaction | coverage_unavailable, highest_known_severity, has_unknown_severity, conflicts[], evidence[]: {source_severity, direction, raw_text, management, source_path/span_start/span_end/checksum/source_hash, subject/interacting concept_ids}, coverage_basis: {basis: reviewed_evidence | reviewed_complete_coverage | limited_coverage_unavailable, release_status, detail}}, limitations[], generated_at (Z)}`.
- Coverage rule: `released_complete` pins every catalog pair reviewed (rows → `interaction_found`/`reviewed_evidence`; no rows → `covered_no_listed_interaction`/`reviewed_complete_coverage`); `released_limited` pins excluded material uncovered (rows → `interaction_found`; no rows → `coverage_unavailable`/`limited_coverage_unavailable` + copied `limitations`; every resolved med listed uncovered because limited scope cannot certify any drug's full coverage).
- Routes (all under `/api/v1`): `POST /ddi/check` with `{medications: [{catalog_drug_id}], dataset_version}` (`extra=forbid`; any active session + `X-CSRF-Token`, `401`/`403`/`404`/`422` per above, standard `ErrorBody`, no tracebacks/secrets); `GET /drugs?query=&limit=&offset=&dataset_version=` (any active session, no CSRF; `{dataset_version, catalog_version, items[]: {catalog_drug_id, concept_id, canonical_name, concept_type}, total, limit, offset}`).
- CLI (unchanged from S18): from `backend/`, `uv run python -m x_insight.ddi build --sources <dir> --terminology <aliases> --output <staging-dir>` + `uv run python -m x_insight.ddi publish --staging <staging-dir> --manifest <reviewed-manifest>`; S19 adds no CLI and no make target.
