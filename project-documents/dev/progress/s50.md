## Scope and synthetic basis

- §1 successful proposal appears unchanged beside editable secondary plan;
  changes persist through reload; visible comparison shows physician edits.
- §2 explicit Sign flushes saves, verifies reviewed per-question
  probabilities/results and final plan, submits exact
  acceptance/encounter/plan/review refs. Pending/failed/stale calculations
  block signing without losing plan text.
- §3 signed view is read-only (original/final probabilities, exact
  attribution/history); print permission follows the declared provisional
  policy. Another physician (and admin read-only) can read signed content
  but not alter it.
- §4 different active physician appends an attributed correction;
  chronology shows original signer and new addendum author/date separately.
  Double-click/retry does not duplicate signatures/addenda.

## What works

- T9 §1: proposal sections render unchanged beside
  `secondary-plan-textarea`; save bumps the plan revision fence; reload
  restores the same text; `plan-compare-*` shows proposal vs plan with
  edited status.
- T9 §2: explicit Sign flushes acknowledged saves then submits exact
  acceptance/encounter/plan/review refs (If-Match + Idempotency-Key
  asserted); pending proposal, failed generation (real T1 409 on partial
  sign), and stale/unsolved currents block `POST .../sign` with
  `proposal-sign-blocked`/`sign-status` denial while plan text is
  preserved.

  64-char hash, plan, per-question results/attribution/history);
  print affordance is wording-only under the provisional policy;
  other-physician and admin reads see signed content without edit/append
  affordances; CPTs are immutable after sign.
- T9 §4: different active physician appends an attributed correction with
  server actor/time; chronology keeps original signer separate from
  addendum author/date; double-click Sign sends one POST and disables

  text without duplication.
