# S41 — Real private MCP transport and context grants (2026-10-09)

S41 is implemented as a scoped-transport slice over S40 snapshots and S44
leases. A worker-owned stdio subprocess exposes exactly one tool
(`get_question_patient_inputs` with `{}` only) and returns the bound
stored projection (`question_key`, `network_version`, `projection_hash`,
`variables[]`) through a real SDK `tools/list` + `tools/call` round-trip.
Grants reuse the S44 `reasoning_grants` rows (hash/binding/revoke/expiry,
no new migration); the opaque grant travels via protected worker
environment only, and every read revalidates the live binding
(grant/lease/deployment, active author, draft encounter, ready run, fresh
fingerprint, projection hash, tool/args, output size) over a SELECT-only
path with bounded generic errors. Concurrent slots use separate
processes/grants; stop/revoke precedes reuse; protocol stays on stdout,
diagnostics on stderr. Fencing stays in `queue.py` (S44, re-exercised in
S47). Synthetic single-question scope per tasks.md S41; T6 is exercised
via temporary probes (official `BT/mcp/test_scoped_transport.py` left for
dev-test). No public listener, patient search/write/inference/shell/file
tool, or direct-call production bypass was added.

T6 behavior (all via real subprocess, never direct calls):

- Discovery returns exactly one tool with the exact empty schema; `call`
  with `{}` returns the bound stored projection (hash/variables match the
  claimed run; `question_key`/`network_version` from stored run/pinned).
- Extra args/unknown tools/forged/missing/expired grants, stale
  fingerprints, and inactive authors fail with bounded generic errors
  (≤200 chars, no secrets/existence); grant Binding is job/batch/run +
  deployment, context comes from protected env + DB only.
- Concurrent A/B grants return own sentinels only (notes never appear);
  revoked grants fail while the sibling slot still reads; stdout carries
  protocol only.
- Oversized output (>65536 canonical bytes) and DB/transport failures
  return bounded errors; `revoke_scoped_grant` + queue terminal/reclaim
  paths revoke; deployment bumps fence old grants via shared `queue.py`
  checks.

## What works

- Real SDK client starts the stdio subprocess, discovers exactly the
  allowed tool with the exact empty schema, calls `{}` and receives the
  bound stored projection.
- Every read validates active account, draft encounter/run, live
  lease/grant, deployment generation, fingerprint/projection hash, tool
  name/empty args, and output size with bounded errors.
- A/B slots and successive contexts isolate (own sentinels, no notes,
  revoke-before-reuse, sibling unaffected, stderr cannot corrupt stdout).
- Oversized/DB/transport failures are bounded; process exit + grant
  revoke cleans up; deployment/lease fencing reuses S44.
