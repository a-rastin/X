## Scope and synthetic basis

- §1 required-action inventory with missing events added at the
  actual transaction/command path. Successful mutation plus event
  are atomic; failed commands record accurate failure metadata
  without false success (`generation.run.success` /
  `generation.run.failed`, `cpt_retry.requested`, enriched
  `actor_id`/`actor_display`/`patient_id` attribution).
- §2 stable attribution survives physician rename/deactivation.
  Original runs, completed slider edits with redistribution,
  resets, calculation outcomes, exact acceptance, and sign events
  carry actor/time/patient/encounter/question/run/revision plus
  required before-after CPT values; no keys or unrelated clinical
  bodies in event payloads.
- §3 physician cannot inspect audit (403); admin filters by
  actor/action/time/target with stable `(occurred_at, id)`
  pagination; no update/delete interface exists (405 on writes);
  append-only database grants probed as SELECT+INSERT-only.
- §4 readable admin table/detail view with correlation
  references, stored-UTC plus viewer-local timestamps, and bounded
  metadata; backup/restore event hook names recorded for S54–S56
  (reserved only, no routes).
