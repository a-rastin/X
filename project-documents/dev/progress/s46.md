## What works

- Five/six-question batches execute strictly in pinned `position` order
  with one eligible question at a time; each question runs the full S45
  pipeline (bounded estimate over real MCP → strict CPT validation →
  effective XML/hash → empty-evidence infer → local template section),
  and the successor is enabled only after the section commits.
- False gates record `not_applicable` without provider cost;
  required-unknown stops the run as `needs_clarification`; later
  requests carry only their own question's persisted projection.
- Completed batches assemble one immutable proposal from stored sections
  + the pinned DDI report (skipped reasons + coverage warnings
  preserved); partial runs stay inspectable but incomplete; missing
  datasets stay explicitly unavailable, distinct from failed releases.
- Freshness holds end to end: relevant edits create a new batch/report
  while the old proposal stays immutable; pinned runs ignore later
  content activation; the LAI step renders only retained
  discussion/review branches.
