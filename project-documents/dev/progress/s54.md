## Scope and synthetic basis

- §1 backup includes database/network XML, original
  baselines/raw estimates, all CPT revisions/results/failures/
  acceptances, signed snapshots/audit, prompts/templates/
  manifests, numerical policies and pinned runtime/configuration/
  dependency locks. Includes adjusted-signed, failed-revision,
  and retained private-draft fixtures.
- §2 concurrent mutation cannot make exported XML inconsistent
  with the database snapshot. Exports derive from the same
  consistent snapshot (REPEATABLE READ transaction), using
  isolated staging where needed.
- §3 usable sessions and the deployment encryption key are
  excluded as specified; encrypted provider values carry an
  explicit key-reentry/recovery note. Administrator
  authorization, bounded synchronous-terminal progress/download,
  and safe audit are required.
- §4 interrupted dump/export produces a failed job and no
  downloadable “complete” archive; retry mints a fresh archive
  and never overwrites a good prior backup. Only documented
  `*.part` temporary artifacts are auto-removed.

## Implementation (reuse-first, minimal diff)

Backend (uncommitted S54 slice, migration 0017):

- New `backend/migrations/versions/0017_backup_jobs.py` +
  `db.py` 0016→0017: `backup_jobs` table (id UUID, terminal
  status, archive path/hash/size, manifest inventory, safe
  counts only — no clinical bodies, no sessions, no deployment
  key).
- New `operations/backup.py` contract (plan §§4.1, 10.2):
  `BACKUP_MANIFEST_VERSION = "backup-v1"`,
  `MAX_ARCHIVE_BYTES` bound, `safe_job` (hashes/counts only),
  `create_backup` (REPEATABLE READ snapshot read over clinical
  tables; only `backup_jobs` writes; XML exported from that
  snapshot, never mutable live files; reproduction uses saved
  CPTs, never new LLM estimates), `get_backup` /
  `read_archive_bytes`, `verify_archive` coherence check
  without touching live state (T10), `*.part`-only cleanup
  (never deletes clinical history). Missing-table content is a
  recorded warning, not a silent pass or a whole-backup
  failure. `IDEMPOTENCY_OPERATION = "backups.create"`.
- `operations/router.py`: `POST /api/v1/backups` (201,
  admin-only mutation with CSRF + optional Idempotency-Key
  replay, synchronous-terminal job) + `GET
  /api/v1/backups/{id}` (admin-only progress/manifest read) +
  `GET /api/v1/backups/{id}/download` (admin-only zip,
  `attachment` + `private, no-store`), 401/403 like audit,
  malformed/unknown IDs 400/404, oversized archive rejected,
  audited atomically (`backups.create(.success/.failed)` with
  actor + `backup_id` + hashes/counts only; denied attempts
  leave no success event).

  (database snapshot + network XML from that snapshot,
  baselines/raw estimates, all CPT revisions/adjustment
  history, results/failures, acceptances, signed snapshots,
  audit, prompts/templates/manifests, numerical policies,
  pinned runtime/config/dependency locks); adjusted-signed,
  failed-revision, and retained private-draft fixtures
  included.

  snapshot (proven by the concurrent-mutation test).
- T10/T1 §3 + T9: admin-only gates (anon 401 / physician
  403 / admin 200 + `private, no-store` on progress/
  download); sessions + deployment key excluded; manifest
  carries the key-reentry note; bounded synchronous-terminal
  progress/download.
- T10/T1 §4 + T9: interrupted export yields a failed job
  with no downloadable complete archive; retry mints a fresh
  archive path and never overwrites a good prior backup;
  same-key replay returns the prior job; only `*.part`
  temp files auto-removed.
- Verify/exit per tasks.md S54: inspected through the
  backup interface/manifest and coherence-checked into
  disposable staging — green per the counts above (backup
  T10/T1 8; HTTP 319 + 1 deselected; worker/probability 80;
  tsc clean; build 67 modules; backups e2e 8/8; regressions
  7 + 6 chromium). A downloadable zip alone was not treated
  as recoverability evidence.

  NOT tamper-proof, and no manifest, label, or payload hash
  here claims otherwise.
