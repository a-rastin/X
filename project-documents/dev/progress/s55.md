## Scope and synthetic basis

- §1 valid app-generated archive stages into isolated staging,
  reports backup date/schema/content/checksums/impact, and returns
  an immutable confirmation digest.
- §2 path traversal, absolute path/symlink, oversized expansion,
  corrupt hash, unsupported schema, missing artifact, and malformed
  database content fail before live mutation.
- §3 untrusted upload staged with restricted permissions and
  resource limits; no superuser execution, no host file/program
  access. Singleton identity, references, and model/effective-artifact
  consistency validated through supported inspection commands.
- §4 failed staging leaves current patients/login/jobs unchanged;
  replacing upload or expiry invalidates prior confirmation. UI
  exposes validation errors and key-reentry consequences, never an
  enabled premature Commit.

Depends DONE: S54 (consistent full backups + `backup-v1` manifest +
`backups.create(.success/.failed)` precedent), S49 (atomic sign +
immutable snapshots/addenda), S52 (admin-only audit view). NOT
modified: commit/switch/rollback (S56), identity pager surface,
migrations beyond 0018.

Synthetic scope explicit: real admin/physician sessions and real
patient/draft/medication/batch/worker/adjust/reset/accept/sign/backup
flows in T10/T1 style; synthetic two-node content only; no
clinical content. Expected literals are worked fixtures, never
implementation output.

## Implementation (reuse-first, minimal diff)

Backend (uncommitted S55 slice, migration 0018):

- New `backend/migrations/versions/0018_restore_jobs.py` +
  `db.py` 0017→0018: `restore_jobs` table (id UUID, terminal
  validation status, staging path/digest, impact report, safe
  counts only — no clinical bodies, no sessions, no deployment
  key).
- New `operations/restore.py` contract (plan §10.3 steps 1–3,
  ~1000 lines): `validate_archive_bytes` guards (traversal/
  absolute/symlink, compressed/uncompressed limits, checksums,
  schema/application compatibility), singleton-identity check,
  reference and model/effective-artifact consistency checks,
  impact report (timestamp, backup identity, replacement impact,
  missing-key consequence), immutable confirmation digest with
  `commit_available: false`, and no commit route. Failed staging
  leaves live state intact; only successful staging expires
  priors (failed-replace expiry fix).
- `operations/router.py`: `POST /api/v1/restores/validate`
  (admin-only mutation with CSRF, bounded staging job) + `GET
  /api/v1/restores/{id}` (admin-only progress/impact/digest
  read), 401/403 like backups/audit, malformed/unknown IDs
  400/404, `private, no-store` on reads, audited atomically;
  denied attempts leave no success event.
- `app.py`: per-route body limit (`POST /restores/validate` →
  `MAX_ARCHIVE_BYTES` 100 MiB, default 1 MiB elsewhere).

Frontend (uncommitted S55 slice):

- `features/admin/restores/api.ts` (new): validate/status
  client reusing `identity/api.ApiError`; reads carry
  no CSRF, like backups/audit reads.

  upload/validate + terminal status + impact report + digest +
  key-reentry note, with busy/status/error states, no fake rows

- `app/router.ts`: `#/restores` route (`restores` key, admin

  `role=status`/`alert`, keyboard-reachable actions.
- Stable hooks for dev-test: `#restores-*` (heading, file,
  validate, status, impact, digest, error).

Tests (uncommitted S55 slice):
