### How the symptom can arise

1. The worker resolves the provider settings revision pinned to a job and creates a bounded adapter; later settings changes do not rewrite the pin ([worker](../backend/src/x_insight/reasoning/worker.py#L401), [issue 15](issue-15.md)). A valid worker environment capability override wins over the saved mode. The API and worker may have different environments.
2. The coordinator estimates CPTs for the applicable questions. The adapter sends the question prompt, projected inputs, network/CPT contract and tool interface to the provider. The resulting JSON must pass strict complete-CPT validation; only then can deterministic inference and proposal assembly proceed ([provider](../backend/src/x_insight/reasoning/provider.py#L349), [coordinator](../backend/src/x_insight/reasoning/coordinator.py#L949)). A generation failure can therefore prevent a proposal, but readiness, a missing baseline, DDI, or the display path can also prevent visibility. None is proven to be this patient's cause.
3. The response adapter uses nonempty `content` before `reasoning_content`, falling back to the latter when content is empty ([provider](../backend/src/x_insight/reasoning/provider.py#L577)). Invalid JSON or CPTs lead to `PROVIDER_INVALID_RESPONSE`; the validator reason is currently discarded and the response finish reason is not inspected ([provider](../backend/src/x_insight/reasoning/provider.py#L1043)). Thus existing diagnostics might not distinguish truncated output from a malformed or contract-invalid answer. This is an observability limitation, **not** evidence that truncation occurred.
4. Capability detection is advisory and does not select the saved mode. A successful small probe cannot establish that the full CPT response will work ([provider configuration](../backend/src/x_insight/reasoning/provider_config.py#L554), [probe](../backend/src/x_insight/reasoning/provider.py#L715)). A narrowly classified HTTP 400 response-format rejection causes one request without `response_format`; other failures follow the existing classification ([provider](../backend/src/x_insight/reasoning/provider.py#L960)).
