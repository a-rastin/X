Why does a healthy NVIDIA URL fail provider save?

Long image

A

Answer

Save does not test whether the URL is reachable. It rejects integrate.api.nvidia.com because that host is not on the operator allowlist.

  1. Save compares the hostname with X_INSIGHT_PROVIDER_ALLOWED_HOSTS and nothing else.1
  2. An empty list denies every host, including a public API.2
  3. The path is the POST target, and the list does not read it.3
  4. DNS and private-address checks run on Test, not on this save error.4

The denial is this function, called before any settings row is inserted.5

  1. Provider page ↗

    The form sends the URL as typed. It does not hold the allowlist.

  2. PUT api-settings ↗

    Save calls the destination check before inserting a revision.

  3. Host on allowlist? ↗

    The match is the hostname only, and case does not matter. An empty list matches nothing.

  4. 422 denied ↗

    The page shows Provider base URL is not an allowed destination. No row is written.

Exact host only

The list stores hostnames only. A scheme, path, port, or parent domain does not match. nvidia.com does not allow integrate.api.nvidia.com.

4

Where does the running API read that list?

Save reads the API process environment on each request.2 A file edit is invisible until that process starts again with the new value.

PlaceRole on this error
Provider pageSends the URL. It does not hold the list.7

Worker environmentNot used on save. Needed later for generation.9

Restart after the edit

make dev does not load .env into the API.10 Export the file in that shell, then restart the API.11 Code reload does not pick up a new list. This checkout has no .env file. The API you are saving against may be another process.
